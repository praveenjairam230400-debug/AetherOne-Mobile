# Aether One PC 0.6

Close all Aether windows, extract the ZIP and run AetherOne.exe. Windows x64 and current Microsoft WebView2 Evergreen Runtime are required; .NET is bundled. The EXE is unsigned. The existing default profile remains %LOCALAPPDATA%\AetherOnePC\Profile. This is Aether's native Windows shell using WebView2/Chromium, not a separate rendering engine or a Brave fork.

## Resource policy and request routing
0.6 keeps one shared WebView2 environment per profile/window. Native request filters route potential blocker matches and explicitly disabled images through the app; ordinary resources no longer pass through the C# blocker handler. Block decisions still parse and validate the hostname, preserving first-party exemptions and ad-blocker/site toggles. Inspector request counts now mean app-intercepted resources, not all engine traffic.

Hidden pages request native suspension; where that is unavailable, the app uses the engine's Low-memory target. Returning pages resume/restore Normal. Every 15 seconds, the controller samples known-process private memory and Windows available physical memory. The normal soft budget is physical RAM / 32, bounded between 256 and 512 MiB; pressure reduces it to 192 MiB. These are decision thresholds, NOT enforceable engine/process caps. Protected work can exceed them. Reclamation begins above the budget plus 12.5% hysteresis. Candidate priority accounts for inactivity, tab visits and observed navigation completion cost.

Ordinary candidates need two minutes inactivity; Windows memory pressure permits 20-second candidates. Active, pinned, loading, audio, detectable input and pages containing frames are excluded from automatic unloading. Active downloads defer reclamation. Unknown script-only state, uploads and custom app state cannot be comprehensively detected. Pin tabs whose state must remain resident. Unloaded pages reload on selection, with best-effort URL/scroll/zoom restoration; original JS heap, in-page history and full app state are not serialized. Manual Sleep retains its confirmation about potential state loss. Home/native views are released when no longer needed; extension management keeps its required view.

Performance settings show current known-process private memory, live-view counts, the last decision and tab retention states. Private committed memory differs from Task Manager resident memory; summed working sets can double-count shared pages. No page text or form contents are persisted by the controller.

## Optional article rendering
Site settings offer an OFF-by-default experimental efficient-article toggle. A small stylesheet applies the engine's `content-visibility:auto` with intrinsic-size hints to direct articles under `main` and matching conversation article elements. It does not remove DOM content, replace the memory allocator or stop website timers. The stylesheet also matches articles added by the website later, without mutation polling. It can change layout/scroll estimates; turn it off per site if needed. This is not equivalent to the unbuilt experimental Chromium cache controller. The CI correctness fixture verifies DOM text/input retention and reversibility; no whole-browser RAM or speed saving is inferred from that fixture.

## Evidence
CI compares the previous 0.5 app against 0.6 on the same runner. The smoke-only loopback origin is exempted from HTTPS upgrading during this test; no certificate exception or production HTTP policy change is made. Five navigations each fetch 64 resources from a real loopback HTTP server, recording handler interceptions and completion time. The eight-page memory fixture touches a 32 MiB buffer and draws a canvas per page. It reports total known-process private memory before/after reclamation and after closure. Inactivity timestamps are advanced for both versions; 0.6 additionally injects a 256 MiB soft test budget. It checks active/pinned/draft protection and 0.6 scroll/zoom restoration. This is a policy comparison, not identical settings or a measurement of authenticated ChatGPT/Gmail on your ASUS. Blank startup is reported separately and is not representative of browsing.

## Interaction fixes
Bookmarks immediately update the bar and filled icon and open an editable saved confirmation with Done/Remove. Bookmarks manager Open buttons are tested. Tab closure is limited to a 24-pixel close control with a hover highlight; clicking tab-body edges does not close it. Active closure prefers the right neighbor. Close tabs to the right and Close other tabs keep pinned pages. Rapid closing holds tab widths until the pointer leaves. Menus and address suggestions dismiss on outside mouse clicks, including WebView2 clicks. A mouse hook runs only while a popup is visible; it does not capture keystrokes or retain input. Closed popup controls are disposed. Actual settings pages remain tabs; transient menus dismiss.

Website-only menu actions are disabled on native/new-tab pages rather than silently doing nothing. Reload refreshes native settings or reloads an unloaded web tab. Existing back/forward, find, print, downloads, engine selection, profiles, site controls, ad blocker switches, theme switches and bookmark visibility remain available. Search predictions go to Google after a 220 ms typing pause and can be disabled in Search engine settings. URL/email-like input is excluded; submitted searches can use Google, Brave, Bing or DuckDuckGo.

## Extensions and downloads
For Chrome Web Store installation, use Aether's Install extension button above the listing or paste the listing URL into Extensions. The native Add to Chrome mechanism is not Aether's installer. CRX3 download uses Google's HTTPS update endpoint, verifies the developer signature and expected ID, then extracts bounded files and prompts for declared permissions. Compressed limit remains 100 MiB; unpacked limit is now 512 MiB, fixing the reported 100 MiB rejection. Path/link checks and a 20,000-entry limit remain. The exact AdBlocker Ultimate package and Dark Reader are tested in isolated CI profiles; neither is bundled into the production profile. Extensions can add significant memory and CPU cost. Automatic extension updates and all full-browser extension APIs are not implemented. Options/popup entries open as tabs. Signature verification proves identity/integrity, not safety.

Downloads support destination choice, ask-before-save, cancellation and folder opening. Current-window download history is not persisted. Profiles use separate folders and windows; there is no account sync, password vault, VPN, Rewards or Tor implementation. Spaces, notes, split comparison and Reading Tools remain removed. Existing web tabs/bookmarks/cookies are retained. Certificate validation and normal engine security are enabled. Ad filtering is a basic host filter, not Brave Shields/EasyList equivalence. No universal instant-loading, zero-overhead or lowest-resource-browser claim is made.
